# 小窝

版本：`0.5.16`

小窝是给 AstrBot 和主人共同使用的私有空间框架。它不是单纯的日记插件，而是一个可以不断扩展的“小窝”：bot 可以在这里写日记、保存图片、整理人物印象、检索过往记忆，也可以通过模块化生态继续长出新的能力。

## 它能做什么

- 写日记：按私聊或群聊建立独立日记本，避免不同群的记忆串在一起。
- 查记忆：按日期、关键词、人物、事件和情绪线索搜索，不会一次把整本日记塞给模型。
- 存媒体：保存图片、语音和附件，记录备注、保存日期、大小、文件夹和回收站。
- 发原图：bot 可以按用户要求从小窝媒体库发送原图。
- 人物印象：在开关允许时，让 bot 根据稳定证据整理人物印象，而不是看到名字就乱建档。
- 备忘录：用纸条板保存账号提示、聊天片段、名言、待办，以及 bot 认为值得短期或长期记住的琐碎事项。
- 模块管理：在 WebUI 里启用、关闭和配置官方模块、自定义模块、拓展包和外观模块。
- 外观替换：小窝 WebUI 支持官方外观模块，也支持用户自定义主题和页面。
- 首次引导：第一次进入 WebUI 会出现遮罩式引导，按高亮位置说明外观、模块、日记、媒体和备忘录入口。
- 链接安装：模块控制台可以从 GitHub 仓库或 zip 链接安装模块包，并在覆盖前自动备份。
- 导入导出：可以按日记、媒体、人物印象、备忘录、个性化前端等范围备份和恢复，并在导入时显示数据健康摘要。

## 快速开始

1. 安装插件并重启 AstrBot。
2. 打开插件配置，只改这几项：
   - `WebUI 监听地址`
   - `WebUI 端口`
   - `WebUI 登录密码`
   - `小窝管理员 QQ`
3. 访问小窝 WebUI：

```text
http://服务器IP:28080
```

4. 在 WebUI 的“设置”里配置模块、日记本、媒体策略、人物印象和外观。
5. 回到 QQ 里问你的 bot：

```text
这是我们共同的小窝吗？
```

bot 通常比你更清楚这里能做什么，因为小窝会向 bot 注册工具和隐藏规范。

## 配置原则

AstrBot 插件配置只保留启动和访问项。具体功能不要在插件配置里反复设置，统一进入小窝 WebUI。

插件配置保留：

- 是否启用 WebUI
- WebUI 监听地址
- WebUI 端口
- WebUI 登录密码
- 小窝管理员 QQ
- 小窝数据目录
- 小窝时区

WebUI 负责：

- 模块开关
- 日记本绑定
- 写日记时间
- 日记推送格式
- 图片推送模板
- 媒体保存策略
- 人物印象策略
- 备忘录写入策略
- 非管理员权限
- 外观模块
- 导入导出

## 模块化生态

小窝把能力分成几类：

- 官方功能模块：日记、媒体、人物印象、备忘录、小窝 WebUI。
- 官方全局外观：纸庭、玻璃小屋、夜间工作室三套内置外观，在“设置 → 外观设置”中切换。
- 自定义完整模块：可以替代或扩展官方模块。
- 拓展包：挂在已有模块旁边，补充统计、展示、同步、玩法等能力。
- 外观拓展：替换全局前端或补充局部视觉能力。

每个模块都应该有自己的目录、说明和冲突声明。完整模块可以声明替代关系，拓展包可以声明依附目标。这样小窝能在 WebUI 里提示风险，而不是让用户自己猜。

官方外观不是写死在页面里的皮肤，而是可在“设置 → 外观设置”里切换的真实模块。`0.5.15` 内置的三套外观分别偏向长期阅读、通透管理和夜间维护；模块控制台保留小窝 WebUI 这个功能入口，但官方全局外观样式不再作为普通模块卡片散落展示。用户自己的主题应放进 `framework/user_custom/webui/`，避免插件更新覆盖。

## 已注册工具

bot 可以调用这些小窝工具：

- `nest_status`：检查小窝状态。
- `bind_notebook_origin`：管理员让 bot 把某个日记本绑定到当前会话的真实协议来源。
- `write_diary`：写入或更新日记。
- `read_diary`：读取指定日期日记。
- `search_diary`：搜索日记片段。
- `push_diary`：把日记按设置推送为文字或图片。
- `attach_media`：保存图片、语音或附件，并写入隐藏备注。
- `send_media`：从媒体库发送原图。
- `list_impressions`：列出人物印象。
- `read_impression`：读取人物印象。
- `write_impression`：写入或更新人物印象。
- `delete_impression`：删除人物印象。
- `write_memo`：写入备忘录纸条，可标记来源、标签、置顶、归档和敏感内容。
- `search_memos`：按关键词检索备忘录。
- `read_memo`：读取指定备忘录。
- `delete_memo`：删除指定备忘录。

插件同时提供 `skills/nest-diary/SKILL.md`。当 bot 需要记忆、写日记、保存媒体或整理人物印象时，会优先走工具层，不应该绕过小窝直接改文件。

## 隐藏规范

小窝会把部分规范作为系统自动提示注入给 bot，例如“写日记要求规范”“媒体备注要求”“人物印象更新策略”。这些内容不是用户输入，也不应该被 bot 输出到聊天窗口。

重要规则：

- 写日记必须基于稳定证据，不编造。
- 人物印象只有在模块开启且策略允许时才更新。
- 不允许新建人物时，bot 不能因为某个称呼出现就自动建档。
- 媒体备注属于隐藏元数据，不应该当成可见回复。
- 备忘录中的账号、密码提示、私人联系方式或敏感片段应标记为敏感内容，WebUI 默认隐藏。
- 非管理员默认没有写入、删除和媒体操作权限。

## 日记本和群聊隔离

推荐为每个群聊或管理员私聊建立独立日记本：

- WebUI 可以填写会话 ID，但协议类型会自动识别，不建议手动改“群聊/私聊”。
- 最稳的方式是在目标群聊或私聊里让 bot 绑定当前会话。
- 页面里显示你写的日记本名称，不显示复杂平台编号。
- 管理员也可以在目标会话里发送 `小窝绑定日记本 <日记本ID>`，或自然语言让 bot“把某个日记本绑定到当前会话”。这会更新该日记本的协议来源、平台、消息类型和会话 ID。
- 合并展示只影响 WebUI 的查看方式，不会把不同群的推送混在一起。
- 如果 AstrBot 适配器升级后把私聊类型从 `private` 改成 `FriendMessage` 这类真实协议名，小窝会自动把旧日记本对齐到新来源，不会再乱建临时日记本。

这样搜索、回忆、推送和写入都能按日记本隔离，减少串群风险。

## 媒体模块

媒体模块支持：

- 图片预览
- 原图查看
- 可编辑备注
- 文件夹整理
- 回收站
- 彻底删除
- 实时容量统计
- 漂浮模式
- 原图发送

媒体保存策略可以在 WebUI 设置为管理员手动保存、允许 bot 自主挑选、或限制 12 小时内保存数量。

## 备忘录模块

备忘录模块是小窝的短纸条板，适合保存不够长到写成日记、但又值得留下的内容：

- 账号提示和临时线索
- 某段聊天内容
- 名人名言或用户特别在意的话
- 待办、想法、bot 自主挑出来的短记忆

每张纸条会记录标题、正文、标签、来源聊天、记录者、创建和更新时间。敏感纸条默认遮住正文；写入策略可以限制为仅管理员、授权用户，或允许 bot 自主挑选记录并设置 12 小时上限。小窝面向个人使用，敏感保护只是基础遮盖；真正的账号密码仍建议放在专业密码管理器中。

## 数据目录

默认数据目录由 AstrBot 插件数据目录管理。典型结构如下：

```text
framework/
  settings/
  user_custom/
modules/
  diary/
  media/
  impressions/
  memos/
imports/
```

`framework/` 保存小窝框架和 WebUI 设置。
`modules/` 保存各模块自己的数据。
`imports/` 保存导入导出相关记录。

## 支持平台

当前主要面向 QQ 场景，插件元数据声明支持 `aiocqhttp`。

## 定时任务建议

大写推荐：优先用 AstrBot 的自然语言未来任务来创建提醒或周期任务，例如“每天 03:00 帮我整理主群日记本”。小窝会把 WebUI 日记本里的“自动写日记”配置同步成 AstrBot 原生未来任务，而不是自己伪造后台消息事件。

每个日记本都会独立同步任务：不同日记本的时间、目标会话、是否推送、推送位置和推送格式互不串联。保存 WebUI 设置或日记本设置后，插件会立即对账 AstrBot 未来任务：该新增的新增，该变化的重建，该关闭或删除的旧任务会删除。

新建日记本和默认日记本的“自动写日记”默认关闭。需要自动写时，请在 WebUI 日记本管理里手动打开，并确认会话目标和推送目标。

## 给开发者

如果要扩展小窝，请优先做模块或拓展包，而不是直接改官方模块。一个合理的模块应该说明：

- 模块 ID
- 模块类型
- 目标模块
- 替代关系
- 冲突关系
- 数据目录
- WebUI 页面
- bot 工具

小窝的目标不是把所有功能塞进一个插件配置页，而是把功能拆成清晰、可管理、能被 bot 调用的模块生态。
